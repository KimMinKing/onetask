# 외부 서비스로 확장할 때의 설계 초안

현재 `socket_lab.cpp`와 `socket_lab_windows.cpp`는 한 연결 또는 데이터그램만 처리하는 루프백 학습 예제다. 별도 [secure-server](secure-server/README.md)는 Linux에서 TLS 1.3, 토큰 인증, 제한된 동시 연결·요청 시간의 첫 구현이다. 아래 운영용 요구 사항 전체가 구현된 것은 아니다. 실제 인증 방식, 서비스 도메인, 배포 환경, 예상 동시 연결 수를 정한 뒤 별도 검증과 확장이 필요하다.

## 별도 서버 구현 상태

- 완료한 첫 단계: Linux 루프백 전용 TLS 1.3, 개인키 권한·키 짝 검사, 본문 전에 토큰 인증, 4096바이트 프레임 상한, 작업자 4개·대기열 4개, 수락 시점부터 5초 마감 시간, SIGTERM/SIGINT 종료, 인증서·권한·느린 요청·연결 상한 통합 검사.
- 아직 운영용으로 부족한 부분: 외부 바인딩 정책과 방화벽, 토큰 발급·만료·폐기·사용자별 권한, 요청률 제한, 인증서 무중단 갱신, 지표·감사 로그, 배포별 부하 검사, Windows 구현, UDP용 DTLS/QUIC 선택. 단일 정적 토큰과 4개 작업자는 실제 서비스 요건을 대신하지 않는다.

## 연결과 자원 경계

1. 수신 주소·포트·최대 연결 수를 설정으로 받는다. 기본값은 루프백이며 외부 바인딩은 TLS와 접근 제어가 준비된 배포에서만 활성화한다.
2. accept 루프와 고정 크기 작업자 또는 이벤트 루프를 사용한다. 연결마다 무제한 스레드를 만들지 않는다. 연결 수, 대기 중인 작업 수, 사용자별 요청률, 총 메모리에 상한을 둔다.
3. 연결 상태를 `accepted → TLS handshake → 4바이트 길이 → 최대 4096바이트 본문 → 응답 → close`로 관리한다. 각 상태와 전체 요청에 별도 단조 시계 기반 마감 시간을 둔다. 한 바이트씩 보내는 피어가 호출별 5초 타임아웃을 계속 연장하지 못하게 한다.
4. 쓰기 큐가 상한에 도달하면 읽기 또는 새 작업 수락을 멈추고, 한도를 회복하지 못한 연결을 종료한다. 부분 송수신, EINTR/WSAEINTR, 정상 FIN, 연결 재설정을 각기 처리한다.
5. 종료 신호를 받으면 새 연결 수락을 중단하고 진행 중인 요청에 짧은 유예 기간을 준 뒤 소켓을 정리한다. 로그와 지표에는 인증 비밀이나 원문 메시지를 남기지 않는다.

## TLS와 인증

- TCP 바이트 스트림만으로는 상대 신원 확인이나 전송 암호화를 제공하지 않는다. 서버 인증서·개인키를 검증 가능한 TLS 라이브러리에 로드하고 TLS 1.3을 우선 사용한다. 클라이언트는 신뢰 체인과 접속한 호스트 이름을 검증한다. 인증서 검증을 끄는 개발용 설정을 운영에 남기지 않는다.
- TLS 완료 후에도 애플리케이션 사용자를 별도로 인증한다. 인증 방식은 배포 환경에 맞춰 세션 토큰 또는 mTLS 중 선택하고, 토큰 유효기간·폐기·권한·요청률 제한을 정의한다. 비밀은 코드나 로그에 넣지 않고 별도 비밀 저장소에서 읽는다.
- 인증 전에는 큰 본문을 읽거나 무거운 작업을 시작하지 않는다. 단, TLS 핸드셰이크 자체에도 연결 수와 시간 제한이 필요하다. TLS 라이브러리의 부분 읽기/쓰기 및 재시도 신호를 이벤트 루프 상태에 포함한다.
- UDP 예제는 평문이다. 이를 외부로 열 계획이라면 TCP용 TLS를 그대로 적용할 수 없다. 요구 사항에 맞는 DTLS 또는 QUIC 라이브러리와 인증·재전송·중복 처리·증폭 방지 설계를 별도로 선택한다.

## 메시지와 관측

- 4바이트 길이 접두부는 네트워크 바이트 순서로 해석하고 **본문 할당 전에** 4096바이트 한도를 검사한다. 응답 크기에도 같은 한도를 둔다. 프로토콜 버전·메시지 종류·요청 ID·인증 오류 형식을 명시하고, 잘못된 입력은 연결을 닫거나 작은 오류 응답으로 처리한다.
- 연결 수·핸드셰이크 실패·시간 초과·크기 초과·읽기/쓰기 큐 길이·요청 지연을 집계한다. 클라이언트 주소는 필요한 기간과 범위만 기록한다.
- 인증서 갱신과 키 교체, 배포 롤백, 포트·방화벽 설정을 배포 절차에 포함한다.

## 구현 전 통과 기준

- Linux와 Windows에서 정상 연결, 헤더 분할·합침, 조기 종료, 느린 피어, 한도 초과, 여러 동시 연결, 종료 중 요청을 자동 검증한다.
- 잘못된 프레임·인증 입력에 퍼징을 적용하고 주소/정의되지 않은 동작 검사 또는 동등한 메모리 검사를 수행한다.
- 자체 서명·만료·호스트 이름 불일치 인증서가 거부되는지, 인증 없는 요청이 제한되는지, 백프레셔 한도에서 메모리가 안정적인지 확인한다.
- 외부 바인딩·실제 인증서·방화벽 변경은 운영 환경 결정 후 별도 검토한다.
